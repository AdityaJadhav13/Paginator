# ADR-002: Isomorphic, deterministic composition engine

**Post-review status (2026-10-07):** **SUPERSEDED by ADR-017.** Client-side composition is now an optimisation that must prove it is needed. The determinism rules below carry over to whichever kernel is chosen. The TS-specific items (harfbuzzjs, ICU4X WASM, JS Math restrictions) apply only if Option A or D wins EXP-ENGINE.

_Original text (2026-10-07, pre-review) follows unchanged; its "DECIDED" wording is superseded by the status block above (ADR-021)._


**Status:** DECIDED. Resolves RD05 tentatively; it is finalised after the Phase 0 parity run.

## Decision
- `packages/compose` runs the **same pinned `.wasm` artefacts** in browser workers and in Node workers:
  - harfbuzzjs, for shaping, glyph outlines and hb-subset;
  - an ICU4X build with custom data, for UAX#14/#29 segmentation, bidirectional text (UAX#9) and NFC normalisation.
- Internal unit: integer micro-points.
- Lint forbids the following in `compose` and `layout-gen`:
  - transcendental Math functions and `**`;
  - `Intl`, `normalize` and `localeCompare`;
  - `Date` and unseeded random numbers;
  - iterating maps or sets in unsorted order.
- The server is authoritative. When the client's result hash differs, the server's pages replace the client's, telemetry is recorded, and the user is not blocked.
- If the engine version differs between client and server, the document opens read-only until the user reloads.
- B's font registry, shaping and Knuth–Plass code are ported against golden fixtures generated by the oracle.

## Rationale
- Basic arithmetic and `sqrt` give identical results in every JS engine. `Math.exp`, `Math.pow` and related functions may differ in the last bit between V8 and JavaScriptCore.
- The ICU and Unicode versions behind `Intl` differ between browsers.
- So determinism across browsers requires both measures: integer arithmetic and pinned WASM.
